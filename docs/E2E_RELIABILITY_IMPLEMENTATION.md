## 验证覆盖

复验命令（使用新的隔离临时目录，不指向历史任务）：

```powershell
.venv/Scripts/python.exe -m pytest -o addopts='' -q --basetemp=work/e2e-verification-new --tb=short --show-capture=no --disable-warnings
.venv/Scripts/python.exe -m ruff check pathmnist gate_a
```

`tests/test_e2e_reliability.py` 调用真实上游 Manager、生成/调试节点路径、Journal、验收、checkpoint、阶段转换、导出、合同验收、冻结、测试预检和单次测试执行器。只替换外部模型服务、运行器及进程执行容器为同步测试替身，不预填实验阶段完成状态。

- 三种数据输入：NPZ、图片目录、带患者分组的 CSV 清单。
- 每种输入覆盖一次对比和双种子对比。
- 主指标矩阵覆盖 accuracy、macro_f1、class_f1、基线锁定类别对平均 F1；NPZ 另覆盖启用调参和消融的完整四阶段。
- 全四阶段串联发现并修复额外问题：唯一组件被明确禁用时被误拒绝；消融无提升/同分时选择了继承的完整模型。现在消融选择限制在本阶段有效生成节点内。
- 注入种子失败，检查恢复只补失败种子；已完成 Manager 再调用不会新增训练或模型请求。
- 注入测试结果回执已写、阶段提交失败，检查恢复不再次运行验证或测试模型。
- 其他回归覆盖选择身份、失败诊断保留、helper 预算、架构说明文字、单次统计、缓存投影丢失、PDF 重启修复上限、不确定收费暂停。

测试运行器只产生确定性样例预测与占位权重，不能验证真实 PyTorch checkpoint 可加载、CUDA 行为或训练质量。此串联用例不是完整论文归档验收。
